# ติดตั้งเฟส 1 — Google Sheets + Apps Script

ทำครั้งเดียวด้วย **Gmail ของระบบ** (ไม่ใช่ Gmail ส่วนตัว) ใช้เวลาประมาณ 15 นาที

## 1. สร้างไฟล์ Google Sheets หลัก

1. ล็อกอิน Gmail ของระบบใน Chrome (แนะนำให้ใช้ Chrome profile แยก จะไม่สลับบัญชีผิด)
2. เปิด https://sheets.new
3. ตั้งชื่อไฟล์ เช่น `StockCount_Master`

## 2. วางโค้ด Apps Script

1. ในไฟล์ Sheets เมนู **ส่วนขยาย (Extensions) → Apps Script**
2. ตั้งชื่อโปรเจกต์ (มุมซ้ายบน) เป็น `StockCount`
3. ไอคอนเฟือง **การตั้งค่าโปรเจกต์ (Project Settings)** → เขตเวลา (Time zone) เลือก **(GMT+07:00) Bangkok**
4. กลับมาหน้า **ตัวแก้ไข (Editor)** แล้ววางไฟล์ 3 ไฟล์ตามตารางนี้

| ไฟล์ใน Apps Script | ชนิด | คัดลอกจาก repo |
|---|---|---|
| `Code.gs` (มีอยู่แล้ว ลบของเดิมทิ้งทั้งหมด) | Script | `gas/Code.gs` |
| `Core` | กด **+ → Script** แล้วพิมพ์ชื่อ `Core` | `gas/Core.gs` |
| `Admin` | กด **+ → HTML** แล้วพิมพ์ชื่อ `Admin` | `gas/Admin.html` |

วิธีคัดลอก: เปิดไฟล์ใน GitHub แล้วกดปุ่ม **Copy raw file** (ไอคอนสองแผ่นซ้อนมุมขวาบนของไฟล์) แล้ววางทับทั้งหมด

> ชื่อไฟล์ `Core` และ `Admin` ต้องสะกดตรงนี้ทุกตัวอักษร ไม่ต้องพิมพ์ .gs หรือ .html ระบบเติมให้เอง

5. กด **บันทึก** (ไอคอนแผ่นดิสก์ หรือ Ctrl+S)

## 3. รันครั้งแรกและให้สิทธิ์

1. ช่องเลือกฟังก์ชันด้านบน เลือก **setupSheets** แล้วกด **เรียกใช้ (Run)**
2. Google ถามสิทธิ์ → **ตรวจสอบสิทธิ์ (Review permissions)** → เลือก Gmail ของระบบ
3. ขึ้นหน้า "Google hasn't verified this app" เป็นเรื่องปกติของสคริปต์ที่เขียนเอง
   กด **ขั้นสูง (Advanced)** → **ไปที่ StockCount (ไม่ปลอดภัย)** → **อนุญาต (Allow)**
   - สิทธิ์ที่ขอ: แก้ไข Google Sheets และสร้างไฟล์ใน Google Drive (เก็บสำเนาไฟล์ที่นำเข้า)
4. รอจนบรรทัดล่างขึ้น "การดำเนินการเสร็จสมบูรณ์" แล้วกลับไปที่แท็บ Sheets

> หรือรีโหลดหน้า Sheets แล้วกดเมนู **ระบบตรวจนับ → ตั้งค่าชีต (ครั้งแรก / ซ่อมชีตที่หาย)** ได้ผลเหมือนกัน
> ต้องทำเองครั้งแรกครั้งเดียว เพราะ Google ต้องให้เจ้าของบัญชีกดอนุญาตสิทธิ์ก่อน ระบบสร้างให้อัตโนมัติไม่ได้

ผลที่ควรเห็น: มีชีต 16 ชีต (Config, Staff, Devices, Locations, SAP_Snapshot, POS_Snapshot, Barcode_Map, Map_Decisions,
SAP_POS_Compare, Master_Check, Device_Master, Count_Log, Import_Files, Dash_Data, Count_History, Admin_Log)
และใน Google Drive มีโฟลเดอร์ `StockCount_Master_Files`

## 4. เปิดหน้า Admin

1. รีโหลดหน้า Sheets (F5) รอสักครู่จะมีเมนู **ระบบตรวจนับ** ต่อท้ายเมนู "ความช่วยเหลือ"
2. **ระบบตรวจนับ → เปิดหน้า Admin**

## 5. ทดลองด้วยไฟล์จริง (4 พ.ย. 2026)

| ขั้น | ทำอะไร | ผลที่ควรได้ |
|---|---|---|
| 1 | แท็บภาพรวม: รหัสรอบ `2026Q4` วันนับ `04/11/2026` → เปิด/แก้รอบ | ด้านบนขึ้น "2026Q4 · นับ 2026-11-04 · SETUP" และ "ยอดตามบัญชี ณ สิ้นวัน 2026-11-03" |
| 2 | แท็บนำเข้าไฟล์: เลือก `Stock_Shop_POS.xls` → อัปโหลด POS | ป้าย "ยอดชั่วคราว (POS)" ขึ้น, บาร์โค้ดส่งลงเครื่อง 2,318 |
| 3 | แท็บตรวจความพร้อม | บล็อกผ่านทั้งหมด; เตือน: ยังไม่มี SAP, บาร์โค้ด 0000 จำนวน 12 |
| 4 | แท็บภาพรวม: ติ๊กรับทราบคำเตือนทุกข้อ → อนุมัติ Master | "อนุมัติแล้ว ตรงกับข้อมูลปัจจุบัน" v1 |
| 5 | แท็บนำเข้าไฟล์: เลือก `ZMMD002A_Stockbalance_Original_SAP.xls` ติ๊ก "บัญชียืนยัน D−1 แล้ว" → อัปโหลด SAP | ป้ายยอดชั่วคราวหายไป, ยอด SAP รวมเท่ากับยอด POS รวม, **ยังเป็น "อนุมัติแล้ว"** (บาร์โค้ดไม่เปลี่ยน ไม่ต้องอนุมัติใหม่) |
| 6 | แท็บตรวจความพร้อม | จับคู่ 703/703, ยอด SAP ไม่เท่า POS = 0, เติมจาก POS = 4 (U701UMCK0080XX/0150XX/0200XX/0250XX) |
| 7 | แท็บเทียบ SAP กับ POS: กดชิป "เติมบาร์โค้ด" → Export ข้อยกเว้นส่งทีม SAP | ได้ไฟล์ .xlsx ที่บาร์โค้ดแสดงเต็ม 13 หลัก |
| 8 | แท็บบันทึก Admin | มีรายการ SETUP, OPEN_ROUND, UPLOAD_POS, APPROVE_MASTER, UPLOAD_SAP พร้อมเวลาและอีเมล |

ถ้าผลไม่ตรง ถ่ายภาพหน้าจอ (หรือข้อความแจ้งเตือนสีแดงด้านล่าง) ส่งกลับมา

## 6. ตั้งสิทธิ์ไฟล์

- **แชร์** → เพิ่มอีเมลบริษัทของทีมตรวจสอบแบบ **ผู้มีสิทธิ์ดู (Viewer)**
- ผู้ที่เปิดหน้า Admin และกดเมนูได้คือคนที่มีสิทธิ์ **แก้ไข** เท่านั้น ให้เฉพาะหัวหน้าทีมตรวจสอบ
- ชีตที่ระบบเขียนถูกตั้งเตือนก่อนแก้ ถ้ามีคนพิมพ์ทับจะขึ้นกล่องเตือน

## อัปโหลดไฟล์ใหม่ / เริ่มใหม่

| ต้องการ | ทำอย่างไร | ผล |
|---|---|---|
| อัปโหลด SAP หรือ POS ใหม่ | แท็บนำเข้าไฟล์ เลือกไฟล์ใหม่แล้วอัปโหลดทับ (SAP ต้องติ๊กยืนยัน D−1 ทุกครั้ง) | แทนที่ไฟล์เดิม คำนวณใหม่ทันที การตัดสินขัดแย้งเดิมยังอยู่ ถ้าคู่บาร์โค้ด→รหัสเปลี่ยน ต้องอนุมัติใหม่ |
| เริ่มรอบใหม่ทั้งหมด (ช่วงทดสอบ / ใส่ข้อมูลผิด) | เมนู **ระบบตรวจนับ → ล้างข้อมูลรอบนี้ เริ่มใหม่** แล้วพิมพ์ `RESET` | ล้างไฟล์นำเข้า, Barcode_Map, การตัดสิน, Master ที่อนุมัติ และข้อมูลรอบ เก็บ Admin_Log, Master_Check และสำเนาใน Drive ไว้ |

ล้างได้เฉพาะก่อนเริ่มนับ (สถานะ NONE หรือ SETUP และ Count_Log ว่าง) เมื่อเริ่มนับแล้วข้อมูลการนับต้องเก็บไว้ ใช้การปิดรอบแทน

## หมายเหตุ

- ไฟล์ต้นฉบับไม่ถูกแก้: เก็บไว้ใน SAP_Snapshot / POS_Snapshot และสำเนา .csv ในโฟลเดอร์ Drive ของระบบ
- อัปโหลดไฟล์ใหม่ทับได้ทุกเมื่อ ระบบคำนวณใหม่ทันที ถ้าคู่บาร์โค้ด→รหัสเปลี่ยน สถานะอนุมัติจะเปลี่ยนเป็น "ต้องอนุมัติใหม่"
- ถ้าปุ่ม Export ไม่ดาวน์โหลด (บางเบราว์เซอร์บล็อกในหน้าต่าง popup) ใช้ชีต `SAP_POS_Compare` → ไฟล์ → ดาวน์โหลด แทนได้
- อัปเดตโค้ดรุ่นใหม่: วางทับไฟล์เดิมใน Apps Script แล้วบันทึก ข้อมูลในชีตไม่หาย
